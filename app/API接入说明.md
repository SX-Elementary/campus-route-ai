# 接入你的 API：动态实时规划

平台把"排程"和"理解/建议"分开了，这是刻意的设计：

| 层 | 谁来做 | 为什么 |
|---|---|---|
| 排程（谁先谁后、几点走、走哪条路） | **本地确定性引擎** `planner.js` | 可复现、毫秒级、断网可用、不会编造时间 |
| 理解（一句话 → 结构化事项） | **你的 API（可选）** | 自然语言多变，规则难覆盖 |
| 建议（对当前计划给意见） | **你的 API（可选）** | 需要上下文推理 |

模型**不直接产出时间表**：它返回的权重/占用块/事项会经过校验（时长 10–180 分钟、地点必须匹配 54 个点位之一、时间必须合法），再喂给本地引擎重算。这样即使模型胡写，也不会排出一份不可执行的计划。

## 一、两种接法

### A. 本地代理（推荐，Key 不进浏览器）

```powershell
# 推荐：密钥写在站点目录之外的文件里（已为你建好）
#   <招新>\.secrets\llm.env  内容：LLM_BASE / LLM_MODEL / LLM_KEY
python route\llm_proxy.py
# 或临时用环境变量：
$env:LLM_BASE = "https://api.deepseek.com/v1/chat/completions"
$env:LLM_KEY  = "sk-你的key"
$env:LLM_MODEL = "deepseek-chat"
python route\llm_proxy.py
```

用 `http://127.0.0.1:4181/` 打开时 API 会自动启用（同源代理，无需手填 Base URL）。

打开页面 →「今日路线」→「API 设置」：

| 字段 | 填什么 |
|---|---|
| Base URL | `http://127.0.0.1:4181/api/llm` |
| 模型 | `deepseek-chat`（与上面一致） |
| Key | **留空**（Key 在环境变量里） |

代理同时把整个站点也服务起来：`http://127.0.0.1:4181/`。

### B. 直连（图省事，但 Key 会进前端）

「API 设置」里直接填服务商的 `https://.../v1/chat/completions` + Key。
仅建议在自己的电脑、自己的浏览器上这么干。

## 二、接口契约（OpenAI 兼容）

### 1）一句话 → 事项

```http
POST <Base URL>
Content-Type: application/json
Authorization: Bearer <key>        # 走代理时可省

{
  "model": "deepseek-chat",
  "temperature": 0.2,
  "response_format": { "type": "json_object" },
  "messages": [
    { "role": "system", "content": "你是校园日程助理…输出 JSON" },
    { "role": "user", "content": "今晚八点去综训馆训练一个小时" }
  ]
}
```

期望返回（`choices[0].message.content` 是 JSON 字符串）：

```json
{ "tasks": [ { "name": "乒乓球队训练", "poi": "综训馆", "start": "20:00", "end": "21:00", "dur": 60 } ] }
```

- `poi` 可以是点位名（如"综训馆"）或 id（如 `U24`），也行"体育馆"这种模糊说法（会做包含匹配）。
- `start`/`end` 缺失时按 `dur` 从当前时刻顺排；`dur` 缺失时按 45 分钟。

### 2）对计划给建议

```json
{
  "advice": "晚上 20:00 后有 40 分钟空档，建议断网做一组番茄钟；晚饭挪到 21:15 后更稳。",
  "weights": { "research": 1.2 },
  "blocks": [ { "start": "17:30", "end": "18:10", "label": "队里加练" } ]
}
```

- `advice`：≤120 字，直接显示在面板上（带 💡）。
- `weights`：给本地引擎的权重微调（0–3），目前支持 `research` / `meal` / `walk` / `shower`。
- `blocks`：硬占用块（比如临时集合），会作为不可用时段参与重排。

## 三、失败与降级

| 情况 | 平台行为 |
|---|---|
| 没配置 API | 全部走本地：一句话用内置规则解析（能识别"晚上八点/一小时/综训馆"这类说法） |
| 超时（默认 9s） | 自动回退本地解析，面板提示"模型未生效：timeout" |
| 返回非 JSON / 字段非法 | 逐字段校验后丢弃非法项，保留合法项 |
| 模型给出荒谬时间 | 时长夹到 10–180 分钟，时间夹到 00:00–23:59，超出当天的不采用 |

## 四、动态性是怎么保证的

- **起点是"现在"**：每次重排都传 `now` + `atPoi`（我人在哪），已结束的课直接丢弃，正在上的课标"（进行中）"接续。
- **自动触发**：每 15 秒刷新"现在"线；当前事项一结束、或跨过某个时间点，自动重排（45 秒节流，避免狂算）。
- **事件触发**：看板任务增删改（`workbench-tasks-updated`）、改地点、换天/换周/换宿舍、手动点「重排」。
- **性能**：步行时间按 POI 对做缓存，重排从 ~100ms 降到 **1.6ms 量级**（截图里的状态徽标能看到每次的真实耗时）。
- **可解释**：每次重排记录 `engine / reason / ms / now / atPoi`，面板右上角徽标直接显示"本地引擎 · 1.6ms · 15:22 重排 · 任务变化"。
