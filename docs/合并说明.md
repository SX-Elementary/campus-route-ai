## 三、数据怎么流

```
看板任务 (localStorage: personal-research-workbench-v2)
        │  route/view.js 读取（只取未完成、dueDate ≤ 今天）
        ▼
planner.js：任务 = { 名称, 地点(place), 时长(estimate), 偏好时段(slot), 软约束 }
        │  排进当天空隙（偏好时段排不下就顺延，并标注）
        ▼
时间轴 + 地图动线
        │  在路线视图里改"地点"
        ▼
window.dispatchEvent('workbench-set-task-place') → app.js 写入 task.place → save()
```

- 任务的 `place` 是新增字段，只加在任务对象上；**导出备份 / 云同步会自动带上**，因为 sync.js 同步的是整个任务数组。
- 没设过 `place` 的任务会按标题/项目猜一个默认地点（乒乓/球类→综训馆，快递→快递柜，文献/阅读→图书馆，其余→未来警务学院），你改一次就固定。

## 七、动态实时规划（不是静态排一次）

这一版把"规划"从「生成一份当天时间表」改成了「随时从此刻重算」：

| 能力 | 实现位置 | 说明 |
|---|---|---|
| 以"现在"为起点 | `planner.js` 的 `now` / `atPoi` | 已结束的课直接丢弃，正在上的课标「（进行中）」并接续剩余时长 |
| 我在哪 | 右侧「我现在在」下拉（54 个点位） | 换了位置立刻重排，步行时间从当前位置算 |
| 自动触发 | `runtime.js` | 每 15 秒刷新"现在"线；当前事项一结束就重排（45 秒节流防抖）；跨天自动重排 |
| 事件触发 | `runtime.js` | 看板任务增删改、改地点、换天/换周/换宿舍、点「重排」 |
| 步行缓存 | `runtime.js` | POI 对缓存后，重排从 ~99ms 降到 **1.5ms** 量级 |
| 可解释 | 面板右上徽标 | 「本地引擎 · 1.5ms · 15:23 重排 · 任务变化」 |

### API 放在"决策层"，不放在"排程层"

```
一句话 ──[你的 API]──► {tasks:[...]}          ← 模型只做理解
当前计划 ─[你的 API]──► {advice, weights, blocks} ← 模型只做建议
                              │
                              ▼
                    planner.js（确定性排程）
                              │
                              ▼
                     时间轴 + 地图动线
```

- 模型**不直接产出时间表**：返回的 `weights`（权重 0–3）和 `blocks`（硬占用时段）会先校验，再交给本地引擎重算。
- 实测：给一个 `09:00–10:30 队里加练` 的占用块，科研时间从 453 分钟降到 363 分钟，时间轴上出现「占用 · 队里加练」段——说明模型的约束真的进了计算，不是只显示。
- 没有 API 也能用：一句话事项走内置规则解析（能认"晚上八点/一小时/综训馆"），计划照排。

## 十三、实时性与"跨天污染"审计

问题：会不会受上周/前一天同一时段安排的影响？

先说结论：**规划引擎是无状态的纯函数**——每次重排都重新构建一遍，不复用上一次的结果；课表按 `星期 + 周次区间` 过滤，所以第 7 周不会读到第 6 周的课。但审计中发现三条真实的"跨日通道"：

| 通道 | 原来会不会影响 | 现在的处理 |
|---|---|---|
| 查看**非今天**的日子时，把"当前时刻"当成了那天的时刻 | **会（真 bug）**：周四 19:00 去看周三，周三会被当成"从 19:00 开始"，整天课全被跳过 | 只有选中今天才用 `now`；别的日子 `now=null`，从 06:00 排整天，界面标「非今天 · 全天（从 06:00 排）」 |
| 页面开着过零点 | **会**：日期变了但还沿用旧的"今天" | `tick()` 检测日期变化 → 自动切回今天并重排（reason=date-roll） |
| 前几天没做完的任务 | **会**（`app.js` 的 `rollForwardDelayedTasks` 会把 dueDate 顺延到今天并累计 delayCount） | 这是你想要的功能，但必须可见：面板会写「含 N 件延期任务（来自之前日期）」；并加开关「把前些天没做完的任务也排进来」，关掉就只排今天该做的 |

不会被污染的：步行缓存只存"两点之间多少秒"（与日期无关）；宿舍/地点存的是偏好不是日程；每个候选方案都复制一份 tasks，避免 `done` 标记互相污染。

验证（Node 直接跑 runtime）：

```
今天=周四 当前 19:23
看今天   → now=19:23 today=true  首段=19:23 军事理论（进行中）
看周三   → now=null  today=false 首段=06:00 起床 · 洗漱 · 整理内务  科研=536
切回今天 → now=19:23 today=true
```

还有一个"伪实时"的限制要说明：自动重排靠页面里的定时器（15 秒一跳）。**浏览器会把后台标签的定时器节流到约 1 分钟一次**，所以切回页面时如果有延迟，点一下「重排」就是最新状态（重排本身 1–3ms）。

## 十六、周次自动推算 + 吃饭策略（学生荟已排除、外卖成为候选）

### 1）周次不再靠你记

`schedule.js` 里加了 `semesterStart: "2026-09-07"`（第 1 周的周一）。页面加载时自动算：
`第 N 周 = floor((今天 − 起始日) / 7) + 1`，然后

- 页头日期下面固定显示「**第 7 周**」徽标（所有视图都可见）；
- 路线面板的「第几周」自动填成这个值，你手动改过之后就不再覆盖；
- 越界（<1 或 >25）会夹紧到边界并在徽标里提示“日期超范围，请改 semesterStart”。

> ⚠️ 这个起始日是**我反推的**：这台机器的系统日期是 **2026-10-23（星期五）**，而你一直按“第 7 周”在用，
> 于是第 1 周 = 2026-09-07。如果学校的实际教学周不是这样，改 `schedule.js` 那一行即可，其他都自动跟着变。

顺手修掉一个被它暴露的 bug：原来我把算出来的周次**直接写进了计划**，一旦算出 59 周，
所有课程都不在周次范围内 → 计划里一节课都没有。现在只有合法值才会写进去。

## 十九、容错设计：预览 → 确认 → 撤销 → 删除

原来的问题：一句话解析出来就直接写进看板，写错了只能在看板里翻半天手动删，甚至删不掉。
现在补了三层防护。

### 1）解析结果先预览，再确认（从源头挡住误加）

点「解析」后**不再直接添加**，而是列出识别到的事项，逐条可勾选：

```
本地规则解析：识别到 2 条，请确认后添加，已并入日常：洗澡、取快递
☑ 去9号学生公寓    D9 · 20 分钟
☑ 拿洗漱用品       D12 · 10 分钟
自动并入日常安排：洗澡、取快递（不新增任务）
[ 添加 2 条 ]  [ 取消 ]
```

- 取消：输入框内容保留，什么都没写进去；
- 勾选数变化时按钮文字实时变（"添加 2 条" / "请至少选 1 条"）。

### 2）撤销栈（30 步，跨刷新保留）

- 每次改动前把上一版压栈（`save()` 里统一处理，覆盖新增/编辑/拖拽/勾选/删除全路径）；
- 侧边栏「撤销」按钮实时显示剩余步数（`撤销 (3)`）；
- **Ctrl+Z / ⌘+Z** 也能撤（在输入框里不拦截，保留原生文字撤销）；
- 栈存在 `localStorage.xingzhi-undo-stack`，**刷新页面后仍能回退**；
- 撤销后弹出提示："已撤销 · 还剩 N 步可退"；栈空时提示"没有可撤销的操作"。

### 3）逐条删除 + 立即反悔

每张任务卡片底部多了一个「删除」按钮，删掉后底部弹出：

```
已删除「拿洗漱用品」   [撤销]
```

9 秒内点撤销即恢复（与其他改动共用同一个撤销栈）。

### 验证（自动化，非目测）

| 场景 | 结果 |
|---|---|
| 初始 0 条 → 加 2 条 | 2 条，可撤销 2 步 |
| 撤销 1 次 | 1 条 |
| 撤销 2 次 | 0 条 |
| 再撤销 | 返回 false，提示"没有可撤销的操作" |
| 删一条后撤销 | 恢复 |
| 撤销按钮 | 存在，栈空时 disabled |

### 边界（说清楚，避免误解）

- 撤销只覆盖**看板任务**；「计划」本身每次重排都会重算，不存在"脏状态"，所以不需要撤销；
- 导入备份是**整体替换**，有确认弹窗，且会被记入撤销栈（可整体回退）；
- 撤销栈上限 30 步，超出丢最早的。

## 二十、为什么会有"空白时段"？—— 30 分钟门槛与"机动段"
